Yes, `gentoo-kernel-bin` is a **default kernel**, but with a specific Gentoo twist.

When you install `gentoo-kernel-bin`, you are installing a **distribution kernel**. This means it comes pre-compiled with a sane, generic default configuration (very similar to what Fedora or Arch uses) so that it works out of the box on almost any hardware without you having to manually configure it.

If you want a **Hardened kernel** (which includes extra security patches and restrictions to mitigate exploits), the process depends on whether you want to stick with a pre-compiled kernel or compile it yourself.

---

## Option 1: The Quick Way (Pre-compiled Binaries)

Gentoo doesn't provide a separate `gentoo-kernel-bin` package specifically named "hardened". Instead, you use the standard distribution kernel but use Gentoo's **USE flags** to inject the hardened configuration before it installs.

### 1. Enable the Hardened USE flag

Tell Gentoo you want the hardened configuration for your kernels. Run:

```bash
echo "sys-kernel/gentoo-kernel-bin hardened" >> /etc/portage/package.use/kernel

```

### 2. Install (or re-install) the kernel

Now, emerge the package. Portage will fetch the binary and apply the hardened configuration overrides.

```bash
emerge --ask sys-kernel/gentoo-kernel-bin

```

---

## Option 2: The Traditional Gentoo Way (Compile from Source)

If you are running a **hardened profile** (which you can check by running `eselect profile list`), or if you want to compile the kernel yourself for better optimization, you should use the source packages.

### 1. Install the Hardened Sources

Instead of the binary, install the standard Gentoo sources (if you are on a hardened profile, these sources automatically include the Gentoo Hardened patchset).

```bash
emerge --ask sys-kernel/gentoo-sources

```

### 2. Configure with the Hardened Preset

Gentoo provides a tool called `sys-kernel/gentoo-kernel` (without the `-bin`) which can automate the compilation of `gentoo-sources` using the hardened config.

First, set the USE flag for the source tool:

```bash
echo "sys-kernel/gentoo-kernel hardened" >> /etc/portage/package.use/kernel

```

Then, let Gentoo build it for you:

```bash
emerge --ask sys-kernel/gentoo-kernel

```

---

## Crucial Post-Installation Steps

Regardless of which option you chose, you need to tell your system to actually use the new kernel.

1. **Update your bootloader:** If you use GRUB, update your config so it sees the new hardened kernel:
```bash
grub-mkconfig -o /boot/grub/grub.cfg

```


2. **Reboot:** Restart your system.
3. **Verify:** Once you log back in, verify that you are running the hardened kernel by checking the output of:
```bash
uname -a

```


*(You should see "hardened" or specific security extensions listed in the version string).*

> ⚠️ **A Quick Warning on Hardened Kernels:** Hardened kernels restrict certain memory access and system calls. Because of this, certain software (like Wine, VirtualBox, or some proprietary graphics drivers) might require extra tweaking or specific local configuration to run correctly.

Here are the answers to both of your questions to help you figure out what's currently happening on your system and what choice makes the most sense.

---

## 1. Will you have 2 kernels or only 1?

When you change the USE flags and run `emerge`, **you will still technically have both kernels on your disk, but only one will be active.**

Here is how Portage treats `gentoo-kernel-bin`:

* **During installation:** Because you just toggled a USE flag (`+hardened`), Portage views this as an update/reconfiguration of the *same* package slot. It builds/downloads the hardened version, drops it into your `/boot` directory, and automatically uninstalls the old file.
* **In your bootloader:** If you already updated GRUB (or your bootloader of choice), the entry will now point to the **hardened** kernel.
* **The Caveat:** If you didn't clean up older versions (`emerge --depclean`), or if you explicitly have multiple versions of `gentoo-kernel-bin` installed at the same time, the older physical files might still sit in `/boot`. However, your active system will only boot into whichever one you select at the GRUB menu.

---

## 2. Option 1 vs. Option 2: Which is better?

Neither option is strictly "better" in terms of performance or security because **both options apply the exact same Gentoo Hardened configuration**. The difference is entirely about **time, convenience, and how you prefer to manage your system.**

| Feature | Option 1 (`gentoo-kernel-bin` + USE) | Option 2 (`gentoo-kernel` from source) |
| --- | --- | --- |
| **How it's built** | Pre-compiled binary downloaded from Gentoo mirrors. | Compiled from source directly on your machine. |
| **Install Time** | **Seconds.** Fast and lightweight. | **Minutes to Hours** (depending on your CPU). |
| **Disk Space** | Uses very little temporary space. | Requires gigabytes of space in `/var/tmp/portage` to compile. |
| **Customization** | You get the default generic drivers (everything included). | You can use `savedconfig` to strip out drivers you don't need. |

### The Verdict: Which should you choose?

* **Choose Option 1 (The Binary) if:** You just want a secure, hardened system that "just works" out of the box without waiting hours for the CPU to compile a kernel every time there is a security update. *For 90% of users, Option 1 is the smarter, hassle-free choice.*
* **Choose Option 2 (From Source) if:** You are the ultimate Gentoo purist. Choose this if you want to micro-manage your kernel config, strip out drivers for hardware you don't own to make the kernel smaller, or if you are running an optimized CPU architecture (like `-march=native`) and want every piece of software on your machine compiled specifically for your chip.

The `/etc/portage/package.use/installkernel` file handles a different, but closely related, part of the process.

While `sys-kernel/gentoo-kernel` is responsible for **building** the kernel, `sys-kernel/installkernel` is the tool responsible for **moving** that kernel to the right place and updating your system after it's built.

Turning on the `hardened` USE flag in `installkernel` doesn't change the kernel configuration itself; instead, it changes **how the layout of your `/boot` partition is handled and what automated scripts run** during the installation phase.

Here is what you need to know about setting flags for `installkernel`:

---

## What flags should you use in `installkernel`?

For a modern Gentoo setup (whether you are using a default or a hardened kernel), you generally want `installkernel` to automate your bootloader updates so you don't have to manually run `grub-mkconfig` every time.

Instead of just `hardened`, you should check if you need these common flags in `/etc/portage/package.use/installkernel`:

* **`grub`**: If you use the GRUB bootloader, enabling this flag tells `installkernel` to automatically update your GRUB menu every time a new kernel is installed.
* **`dracut`**: If you need an initramfs (which `gentoo-kernel-bin` uses by default to load generic drivers), this flag tells the system to automatically generate a new initramfs for your new kernel.
* **`systemd-boot` / `efistub**`: If you use systemd-boot instead of GRUB.

### Example Configuration

If you are using **GRUB** and the **generic binary kernel**, your `/etc/portage/package.use/installkernel` file should look like this:

```text
sys-kernel/installkernel grub dracut

```

---

## Do you need the `hardened` flag there?

You only need to explicitly add `hardened` to your `installkernel` package.use file if you are using specific hardened layout configurations or if Portage throws a **USE flag conflict** error demanding it.

To be safe and ensure total consistency across your system, you can absolutely add it:

```bash
echo "sys-kernel/installkernel hardened" >> /etc/portage/package.use/installkernel

```

### Summary of the Workflow

1. **`sys-kernel/gentoo-kernel-bin`** looks at its `hardened` flag $\rightarrow$ It downloads the hardened kernel variant.
2. **`sys-kernel/installkernel`** looks at its flags $\rightarrow$ It takes that downloaded kernel, moves it to `/boot`, builds the initramfs via `dracut`, and triggers `grub` to update your boot menu automatically.
